# Spec: queue-grid-controls（队列控制与每图网格）

Label: ready-for-agent

Status: open

## Problem Statement

用户批量导入多张图片后缺乏队列控制能力：无法删除队列中不需要的图片，无法调整导出顺序；"下载全部"只能按导入顺序保存文件。重复导入时只能先手动清除再重新上传。所有图片被迫共用同一套全局网格，个别图片需要不同切法时只能反复改全局设置再改回来。切片文件的实际大小（字节）不可见，用户无法在下载前判断导出体积。

## Solution

结果区每张图片卡片获得删除、上移/下移与单图网格设置能力；每张图片的缩略图上常显文件大小小字。"下载全部"增加正序/逆序开关。header 增加覆盖上传开关：勾选后新上传/拖入的图片替换整个队列（队列中存在未下载图片时先确认）。队列摘要旁新增"清除所有"入口，复用既有清除动作。全部行为遵循现有架构：全局网格设置、切片结果缓存、目录直写导出与导出报告语义不变。

## User Stories

1. 作为批量导入图片的用户，我想删除队列中不需要的图片，这样导出结果不会混入我不想要的切片。
2. 作为批量导入图片的用户，我想用上移/下移按钮调整图片在队列中的位置，这样导出文件按我期望的顺序排列。
3. 作为使用触屏设备的用户，我想用按钮而非拖拽来排序，这样在小屏幕上也能精确操作。
4. 作为删除了某张图片又重新拖入同一文件的用户，我想让切片直接命中缓存而不重新生成，这样重复操作零等待。
5. 作为经常按倒序导出的用户，我想勾选"逆序"让下载全部按队列反向写入，这样文件管理器中按名排序即符合我的习惯。
6. 作为偶尔切换正逆序的用户，我想让这个选择在刷新页面后保留，这样不用每次重新勾选。
7. 作为整理相册的用户，我想勾选"覆盖上传"，这样直接拖入新一批图片就能替换旧队列，不用先清除再上传。
8. 作为覆盖上传的用户，当队列里还有没下载过的图片时，我想先收到确认提示再被替换，这样不会误丢未导出的成果。
9. 作为已把队列全部下载完的用户，我想让新图片直接替换而不再提示，这样覆盖操作零摩擦。
10. 作为单张长图需要特殊切法的用户，我想为这一张图单独设置网格，而不影响其他图片，这样不必来回改全局设置。
11. 作为使用了单图覆盖的用户，我想随时一键回退全局网格，这样取消特殊切法无需手动恢复。
12. 作为移动端用户，我想在全屏层中设置单图网格，这样预设卡片与自定义行列有足够大的触控目标。
13. 作为关注导出体积的用户，我想在原图预览上看到原文件大小，这样导入时就知道源文件体积。
14. 作为关注导出体积的用户，我想在每个切片缩略图上看到切片文件大小，这样下载前就能评估产出。
15. 作为习惯在队列摘要处清空工作区的用户，我想在"队列中有 n 张图片"旁直接点击"清除所有"，这样不用滚回 header 寻找清除按钮。
16. 作为误触"清除所有"的用户，我想先看到确认提示再被清空，这样误触不丢失工作成果。
17. 作为正在等待切片生成的用户，我想让删除/排序/清除在处理中禁用，这样不会与进行中的生成产生冲突。
18. 作为使用暗色主题的用户，我想让新增的角标、按钮、popover 与现有界面风格一致，这样视觉不突兀。

## Implementation Decisions

- **队列操作（删除/排序）**：`useImageSlicer` 新增删除与排序动作。删除仅将图片移出队列并回收其 Object URL 与 tiles 引用；切片缓存条目保留，同内容图片（内容 SHA-256 相同）重新拖入时经缓存命中。排序通过交换队列数组位置实现，仅改变遍历顺序。
- **处理中禁用**：删除、排序、清除所有按钮在 processing 时禁用，与既有"下载此图片"一致；不引入新的在途生成竞态路径。
- **下载顺序开关**：新增"逆序"checkbox，仅影响"下载全部"的遍历顺序——目录直写的写入顺序与传统逐张的触发顺序均按队列副本反转执行；队列本身不移动。逐图下载不受影响。文件命名与重名后缀规则不变。开关状态持久化到 localStorage（并入导出设置载荷或独立键，实施时定），默认正序。ADR-0001 语义不变：目录直写失败重试仍按剩余项顺序。
- **覆盖上传开关**：header 新增 checkbox，状态持久化到 localStorage，默认关闭。勾选后新上传/拖入的图片替换整个队列；若队列存在未执行过下载的图片，先弹确认，用户确定后替换；全部已下载或队列为空则直接替换。"已下载"判定依据逐图下载标记：图片的切片经逐图下载、"下载全部"（目录直写完成该图）或预览保存动作写出到用户设备后置位。处理中勾选并上传按"等效重置再导入"处理，复用既有重置竞态守卫。实现上替换语义为清空队列（回收 URL）后加入新图，缓存条目不主动清除（与删除语义一致）。
- **每图网格覆盖**：`ImageItem` 增加可选覆盖字段（网格身份 + 分割线信息）。有覆盖的图片按覆盖网格生成，无覆盖的图片跟随全局；全局网格改动仍作用于未覆盖图片。每图覆盖不写入 localStorage，随队列清空消失；现有网格设置载荷无需版本升级。生成路径中生效网格按"每图覆盖 ?? 全局"解析后进入既有快照流程；切片缓存键已含每图实际矩形，每图不同网格天然命中不同条目，缓存模块无需修改。
- **单图设置入口**：每张图片卡片的切片区头部（"下载此图片"旁）新增设置按钮。PC（≥960px）以 popover 展示网格预设卡片 + 自定义行列输入（与全局面板同构）；移动端（<960px）以全屏层展示同样内容，底部确认。popover/全屏层内提供"使用自定义网格"一键回退全局。边线擦除不进入单图设置，仍为全局配置。
- **摘要降级**：结果区顶部全局"网格： 1 列 x 1 行"摘要改为每图卡片内各自描述（利用卡片已有切片计数位置）；当队列全部跟随全局时顶部摘要保留全局描述，存在覆盖时逐图描述为准。
- **清除所有入口**：队列摘要文字旁新增"清除所有"按钮，PC 在浮动导出栏、移动端在结果区头部；动作与 header 既有"清除当前图片"完全相同（清空图片/结果/缓存/待交付下载，保留处理配置）；点击弹确认后执行，processing 时禁用。
- **大小显示**：原图与切片以小字角标常显文件字节数（KB/MB 格式化）。原图在导入时记录文件字节数（`ImageItem` 新增字段）；切片直接取 Blob 字节数。角标叠加在原图预览与切片缩略图上。新增用户可见文案默认中文并同步英文文案表。
- **测试接缝**：全部新行为通过两个既有接缝验证，不新建接缝——`useImageSlicer` 组合函数接缝（注入 environment/cache 桩）覆盖队列逻辑（删除、排序、覆盖上传、下载顺序、已下载标记、每图生效网格解析）；组件挂载接缝（`@vue/test-utils`）覆盖 UI 接线（ResultsPanel 删除/排序按钮与大小角标、AppHeader 覆盖开关、DesktopDownloadBar 顺序开关与清除按钮、每图设置 popover）。切片结果缓存模块行为不变，不新增测试面。

## Testing Decisions

- 只断言可观察行为：按钮渲染与禁用态、点击后事件载荷、队列数组变化、缓存命中次数、下载遍历顺序；不测内部中间变量。
- 队列行为集中在 `useImageSlicer` 组合函数测试（既有 harness：注入即时解析的 environment 桩与内存缓存），沿用"上传去重、下载重算、URL 生命周期、latest-wins、重置竞态"等既有用例风格扩展。
- UI 接线集中在组件测试：`ResultsPanel`（删除/排序/大小角标/单图设置入口）、`AppHeader`（覆盖开关）、`DesktopDownloadBar`（顺序开关/清除按钮），沿用既有组件 spec 的 props/emits 断言风格。
- 每个新用例必须带中文 Given/When/Then/防回归注释（仓库测试规范）。
- 下载顺序用桩环境记录遍历序列断言；覆盖上传确认流用确认回调桩模拟同意/取消两分支；已下载标记用桩下载动作置位后断言覆盖行为。

## Out of Scope

- ZIP 打包导出（ADR-0001 已否定）。
- 拖拽排序、序号输入排序（已定上移/下移按钮）。
- 单图级边线擦除、单图导出格式/质量（覆盖仅限网格）。
- 每图覆盖的跨会话持久化（随队列清空）。
- 预览 PhotoSwipe 界面内的大小显示（仅结果区原图与切片缩略图）。
- 展示顺序随逆序开关变化（逆序仅影响导出遍历）。
