# T03 header 覆盖上传开关

Type: grilling
Status: resolved
Blocked by:

## Question

header 增加 checkbox；勾选后新上传/拖入的图片覆盖原队列，而不是追加。需决策：

1. 覆盖语义：新图替换整个队列（清空后加入），还是仅替换同内容图？覆盖时既有 tiles、缓存条目、预览 lightbox 状态如何清理（复用 `resetApp` 的清空语义还是新增更轻的 replaceImages）？
2. 覆盖与内容 SHA-256 去重的交互：勾选覆盖后，若新图与旧队列中某图内容相同，行为如何（跳过、清空其余但保留该图、还是全部替换重新生成）？
3. 开关位置与持久化：header 已有外观/语言/GitHub 控制与"清除当前图片"；checkbox 放置何处、是否持久化 localStorage、默认关闭（追加）？
4. 处理中勾选并上传：与既有重置竞态守卫的关系（等效于 resetApp 再 addFiles，还是需要新路径）？

预算：2 轮讨论。

## Answer

（2026-11-11 讨论确定，含一轮澄清）

1. **覆盖语义**：勾选覆盖后，新上传/拖入的图片替换整个队列。若队列中存在未执行过下载的图片，先提示确认，用户确定后替换整个队列；若全部已下载（或队列为空），直接替换。不保留任何旧图及其切片。
2. **下载状态判定**：以该图片的切片是否已执行过下载（逐图下载或参与过"下载全部"）为准；实现时在 `ImageItem` 上记录下载标记。
3. **开关持久化**：checkbox 状态持久化到 localStorage，每次会话恢复上次选择，默认关闭（追加）。
4. **处理中上传**：按"等效 resetApp 再 addFiles"处理，复用既有重置竞态守卫，不新增竞态路径。
