## ADDED Requirements

### Requirement: 会话内切片结果缓存

系统 MUST 在当前页面会话内为切片生成结果提供内存缓存，一个缓存条目对应一张输入图片与一组生效生成参数产出的完整切片集合。系统 SHALL NOT 使用 IndexedDB 或任何跨页面刷新持久的存储保存切片结果，页面刷新后结果缓存 MUST 为空。

#### Scenario: 相同图片与参数重复生成命中缓存

- **WHEN** 同一张图片（内容标识相同）在同一会话内以相同生效参数第二次请求生成切片
- **THEN** 系统直接复用缓存的 Blob 字节完成物料化，不再执行画布裁切与压缩
- **AND** 展示的切片集合与首次生成内容一致

#### Scenario: 刷新页面后缓存为空

- **WHEN** 用户刷新页面后重新上传同一张图片并以相同参数生成
- **THEN** 缓存未命中，系统重新执行完整生成
- **AND** 不存在任何从持久化存储恢复切片结果的路径

### Requirement: 缓存键构成

缓存键 MUST 由以下字段构成：显式算法版本常量、图片内容标识（主路径为基于文件内容派生的 SHA-256 摘要；WebCrypto 不可用时为其元信息回退标识）、按生成顺序排列的实际切片矩形序列（经与 Canvas 绘制完全一致的统一取整规则整数化后的 x/y/width/height/row/col）、导出格式。当导出格式为 JPG 时，键 MUST 额外纳入 JPG 质量（以整数百分比编码）；当导出格式为 PNG 时，键 MUST 忽略 JPG 质量。键的主路径（SHA-256 摘要）MUST NOT 包含图片文件名或 baseName；WebCrypto 不可用时的元信息回退标识显式豁免此约束（属既有降级行为）。键中的矩形 MUST 与实际绘制到 Canvas 的矩形取整后完全一致。算法版本常量 MUST 在切片算法或参数语义变化时递增，使旧条目自然失效。

#### Scenario: PNG 修改质量不失效缓存

- **WHEN** 导出格式为 PNG 时以相同其余参数、不同 JPG 质量值构造两次缓存键（PNG 下质量调整不触发重新生成，以键等价层面验证）
- **THEN** 两次键完全相同，命中同一 PNG 缓存条目，不重新裁切

#### Scenario: JPG 修改质量生成新键

- **WHEN** 导出格式为 JPG 时用户调整 JPG 质量并触发重新生成
- **THEN** 质量参与键计算，新键未命中，系统重新生成并以新键入缓存
- **AND** 旧键条目按 LRU 规则保留或逐出

#### Scenario: 改名不影响命中且下载名正确

- **WHEN** 同一内容的图片以不同文件名（baseName）构造缓存键并请求生成（该场景经单元测试或绕过内容去重的路径验证；应用内相同内容文件按内容标识去重，不会以两个名字同时入队）
- **THEN** 两者命中同一缓存条目，复用相同 Blob 字节
- **AND** 每个条目物料化后的下载名称基于各自当前 baseName 拼接，命名正确

#### Scenario: 切片矩形不同则键不同

- **WHEN** 用户移动任一分割线或改变边线擦除设置使实际切片矩形变化
- **THEN** 生成的键随之不同，未命中旧缓存

### Requirement: LRU 双重上限与超预算条目

缓存 MUST 同时受双重上限约束：最多 30 个条目、最多 256 MiB 缓存 Blob 字节（各条目 Blob 的 size 之和，MUST NOT 计入画布、解码位图、Object URL 或浏览器其他内存）。写入后系统 SHALL 按最近最少使用顺序逐出条目，直到两项上限同时满足；缓存命中 MUST 将条目提升为最近使用。单个条目自身的 Blob 字节超过字节上限时，该条目的结果 MUST NOT 入缓存，但仍 MUST 完整服务于当前这次预览与导出流程。

#### Scenario: 超出条目上限逐出最久未使用条目

- **WHEN** 缓存已有 30 个条目且写入第 31 个
- **THEN** 最久未被使用的条目被逐出，条目数回落到 30

#### Scenario: 超出字节上限逐出至双限满足

- **WHEN** 写入新条目后缓存 Blob 字节总量超过 256 MiB
- **THEN** 系统从最久未使用开始逐出，直到条目数与字节总量同时回到上限内

#### Scenario: 命中提升最近使用

- **WHEN** 一个非最近使用的条目被 lookup 命中
- **THEN** 该条目成为最近使用，后续逐出时优先级最低

#### Scenario: 单条目超预算不缓存但可用

- **WHEN** 一次生成的全部切片 Blob 总字节超过 256 MiB
- **THEN** 本次结果完整返回并正常用于当前预览与导出
- **AND** 该结果不写入缓存，下次同键请求重新生成

### Requirement: 缓存内容边界

缓存条目 MUST 且仅 MUST 存储 Blob 与稳定切片元数据（行号、列号、宽、高）。系统 MUST NOT 在缓存中存储 Object URL、随机生成的 id、图片元素或文件名。Object URL 的创建与回收 MUST 保留在 `useImageSlicer` 与 UI 物料化层。

#### Scenario: 缓存命中后重新物料化

- **WHEN** 缓存命中并物料化为可展示切片
- **THEN** 系统为每个切片新建 Object URL、按当前 baseName 生成名称与新 id
- **AND** 缓存内不含任何 URL、id 或文件名字段

#### Scenario: 物料化 URL 生命周期归 UI

- **WHEN** 图片被移除或重新生成替换旧切片
- **THEN** 由物料化创建的 Object URL 由 useImageSlicer 既有清理逻辑回收
- **AND** 缓存模块不创建也不回收任何 Object URL

### Requirement: 生成合并与准入控制

相同缓存键的进行中生成 MUST 合并为一次运行，后续请求共享同一结果。以下情况的结果 MUST NOT 进入缓存，也 MUST NOT 替换当前已展示的完整结果：生成失败、被用户取消、切片数量不完整（部分完成）、生成期间生效参数已变化（过期），以及缓存清空之后才完成的工作。展示结果的替换 MUST 采用成功后原子换装：生成期间旧结果及其 Object URL 保持展示，全部成功后才一次性替换并回收旧 URL。处理期间到达的新生成请求 MUST NOT 被静默丢弃：通过待重跑协调在本轮结束后自动补跑，实现最新优先（latest-wins）。

#### Scenario: 并发相同键合并

- **WHEN** 同一图片同一参数的生成尚在进行时再次请求生成
- **THEN** 两次请求共享同一次生成运行，生成逻辑只执行一次

#### Scenario: 失败或取消不入缓存且保留旧结果

- **WHEN** 生成过程抛出错误或用户请求取消
- **THEN** 已产出部分不写入缓存，缓存保持该键未命中状态
- **AND** 旧结果的切片与 Object URL 保持展示有效，未被替换或回收

#### Scenario: 部分完成不入缓存

- **WHEN** 生成提前终止导致切片数量少于键中矩形数量
- **THEN** 该不完整结果既不缓存也不替换既有完整结果

#### Scenario: 过期结果不入缓存

- **WHEN** 生成期间生效参数与发起时不一致（经处理中追加图片触发待重跑、或程序化修改参数）
- **THEN** 该过期结果不写入缓存
- **AND** 到达的新一轮生成请求不被静默丢弃，本轮结束后自动补跑，展示与缓存以最新一轮为准
- **AND** 旧一轮已开始的 tile 生成可自然完成但结果被丢弃

#### Scenario: 清空后完成的工作不入缓存

- **WHEN** 用户执行重置清空缓存后，此前发起的生成才完成
- **THEN** 该结果不写入缓存，也不替换重置后的空工作区

### Requirement: 统一生成物料化路径

上传预览（含追加图片）、参数变化触发的刷新、单图下载、下载全部与自动下载 MUST 共享同一条缓存确保（ensure）与物料化路径：先查缓存，未命中则发起或并入生成，完成后将缓存条目物料化为带 Object URL 与当前文件名的可展示切片。目录选择器与权限准备 MUST 保持在显式用户点击导出路径的最开始，先于任何缓存查找与生成 await。全部命中缓存的生成轮次 MUST NOT 进入切片生成进度阶段，直接进入后续导出或完成反馈；部分命中按未命中切片计数；导出阶段（saving/downloading）的进度语义保持不变。

#### Scenario: 各入口共享同一 ensure 路径

- **WHEN** 分别通过上传、修改参数、单图下载或下载全部触发切片生成
- **THEN** 四类入口经过同一 ensure/物料化逻辑
- **AND** 相同键的下一次请求命中缓存且不重复裁切

#### Scenario: 目录授权先于生成

- **WHEN** 用户在 PC 端点击“下载全部”且目录导出待授权
- **THEN** 目录选择器在该点击触发的同步路径最前被调用
- **AND** 缓存查找与任何生成 await 均发生在授权准备完成之后

#### Scenario: 全量命中不闪现生成进度

- **WHEN** 一次生成请求的所有切片全部命中缓存
- **THEN** 不展示 generating 阶段进度，直接进入导出或完成反馈
- **AND** 导出阶段进度行为与未命中时一致

### Requirement: 重置保留处理配置

重置操作 MUST 清空图片队列并回收其 Object URL、清空待交付下载状态与整个内存切片缓存，同时 MUST 保留全部处理配置：网格预设/自定义身份与行列、手动水平/垂直分割线、边线擦除启用状态/数值/单位/是否含外边缘、导出格式与 JPG 质量。

#### Scenario: 重置后配置不变

- **WHEN** 用户在自定义网格、开启边线擦除、选择 PNG 格式后执行重置
- **THEN** 图片、切片、对象 URL、待交付下载与结果缓存全部清空
- **AND** 网格、分割线、边线擦除、格式与质量设置保持原值

#### Scenario: 重置后缓存不残留

- **WHEN** 重置后重新上传同一张图片并以相同参数生成
- **THEN** 缓存未命中（重置已清空），系统重新执行完整生成
